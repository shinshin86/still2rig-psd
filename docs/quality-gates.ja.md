# 生成されたPSDで確認できていること

[English](quality-gates.md)

`finalize`と`repair`は、次のうち最初の2段階を報告します。後の段階は前の段階を
満たしたうえで報告します。3段階目は`still2rig-psd motion-qa`の結果で、内蔵の
プレビュー用レンダラーで動きを収録して評価します。

| 報告する状態 | 確認できていること | まだ確認できていないこと |
| --- | --- | --- |
| **構造確認済み** | 設定順でPSDを書いて再読込し、必須レイヤー、表示画素、重要な前後関係の構造QAを通過している。QA結果では`structuralPass=true`です。ハッシュは処理全体の別工程で確認します。 | 本物のまばたき・別の口形、変形、実際の動作品質。 |
| **口・閉じ目ファイル自動検査済み** | `mouth_open`と`eye_close`があり、組み込みプレースホルダーではなく、位置合わせと口の数値検査を通過している。JSONでは`productionReady=true`です。 | 絵として自然か、閉じ目の線が適切か、肌との色差や切り抜き境界がないか。フィールド名にかかわらず、完成したリグを意味しません。 |
| **アダプターによる動作確認済み** | `still2rig-psd motion-qa`が`configs/motion-qa-contract.json`の各状態を内蔵レンダラーで収録し、すべての検査を通過している。 | ほかのレンダラー、形式、未検証のポーズでの動作。動きが自然に見えるか。 |

`--preview-placeholders`を使用したPSDは「構造確認済み」にはできますが、
「口・閉じ目ファイル自動検査済み」にはできません。構造が正しいPSDも、Live2Dモデルや完成リグと
同じものではありません。

## 標準のレイヤー前後順

標準構成は、奥から手前の順に合成します。表の後ろにあるグループほど手前に表示
されます。

| 奥から手前 | レイヤー名 | この順番にする理由 |
| --- | --- | --- |
| 1 | `back hair` | 頭と身体の後ろに置くため。 |
| 2 | `bottomwear` | 上半身より後ろに置くため。 |
| 3 | `handwear` | 身体の横にある腕を、服と肩口より後ろに置くため。 |
| 4 | `topwear` | 横にある腕の内側を服で覆うため。 |
| 5 | `neck` | 身体と服より手前、顔より後ろに置くため。 |
| 6 | `ears` | Anime2.5互換の標準的な頭部順を使うため。 |
| 7 | `face` | 顔パーツの土台にするため。 |
| 8 | `eyewhite`、`irides`、`eyelash`、`eyebrow`、`nose`、`facedetail` | 目・眉・鼻などを顔の上に表示するため。 |
| 9 | `mouth_close`、`mouth_open`、`eye_close` | 口と閉じ目を顔の上に表示するため。 |
| 10 | `front hair` | 前髪で額や隠れるべき顔パーツを覆うため。 |
| 11 | `headwear` | 標準構成の最前面に置くため。 |

機械が使う正確な順番は`configs/layer-map.json`にあります。構造QAでは特に、次の
関係を確認します。

- `handwear`は`topwear`より後ろ
- `handwear`と`topwear`は`neck`より後ろ
- `neck`は`face`より後ろ
- `eyewhite`、`irides`、`eyelash`、`eyebrow`、`mouth_close`、
  `mouth_open`、`eye_close`は`face`より手前
- `face`、`eyewhite`、`irides`、`mouth_close`、`eye_close`は
  `front hair`より後ろ

これは、正面向きで腕を身体の横に下ろしたキャラクター向けの安全な標準順です。
すべてのポーズに共通する唯一の正解ではありません。手が胸の前を横切る場合、1枚の
`handwear`だけでは、肩口では服の後ろ、手先では服の前という両方の状態を表せません。
その場合は腕を前後のパーツに分けるか、PSD構成自体を拡張する必要があります。
レイヤー差し替え機能は既存レイヤーの画像を置き換えられますが、この前後分割を
新しく追加する機能ではありません。

## 口と目を実際に動かすために必要な画像

通常の静止画像には、開いた目と1種類の口しか写っていません。閉じ目や別の口形は
元画像から正確には分からないため、実際の切り替えを確認するには、元画像と同じ
キャンバス寸法・位置の透過PNGを用意します。

| ファイル | 必要になる場面 | 内容 |
| --- | --- | --- |
| `mouth_open.png` | 本物の口切り替えに必須 | 位置を合わせた開き口だけを描き、それ以外は透明にする。 |
| `eye_close.png` | 本物のまばたきに必須 | 左右の閉じ目だけを位置合わせし、それ以外は透明にする。 |
| `mouth_close.png` | 必要な場合だけ | 元画像から取り出した閉じ口が不適切な場合の差し替え。 |

口の周囲に白色や肌色の四角形を含めないでください。口画像には顔の一部を切り抜いた
パッチではなく、口そのものだけを残します。すべての表情画像はPSDと同じキャンバス
寸法に合わせます。

`--preview-placeholders`は、WebUIの操作確認用に閉じ口を開き口の場所へコピーできます。
本物の開き口を作る機能ではないため、スライダーを動かしても見た目が変わらない場合が
あり、「口・閉じ目ファイル自動検査済み」にはなりません。

## 元画像から作る仮の表情

これは、ほかに表情画像を用意できない場合の応急処置です。次のうち、使える最初の
方法を選んでください。

1. 描いた`eye_close.png`と`mouth_open.png`を`--expressions`で渡す。
2. 画像生成ツール(Codexの画像生成など)で作り、元画像のキャンバスに位置を
   合わせたファイルを`--expressions`で渡す。位置合わせと口の検査を通過する
   必要があります。
3. 以下で説明する`derive-expressions`の仮の表情を使う。

仮の表情は形が決まっています。閉じ目は上まつげの線を上下反転して平たくしたもので、
開き口は閉じ口の線の下に小さな開きを描いたものです。笑った閉じ目や丸く開いた口は
表現できず、横目のキャラクターでは黒目の位置と合わない場合があります。

`still2rig-psd derive-expressions JOB`は、組み立て済みのレイヤーから仮の開き口と
閉じ目を描きます。閉じ目は上まつげの線を上下反転して平たくしたものです。
作った画像は`--expressions`ではなく`--preview-expressions`で渡します。

```bash
npm run still2rig-psd -- derive-expressions demo
npm run still2rig-psd -- repair demo --preview-expressions .still2rig-psd/jobs/demo/preview-expressions
```

PSDに組み込まれるため、プレビューでまばたきと口の動きを確認できます。両方の
レポートには`previewExpressions`として記録され、描かれた素材ではないので
`productionReady`は`false`のままです。2段階目に進めるには、描いた表情画像を
`--expressions`で渡して置き換えます。

## 実行する検査

組み立て処理は`configs/layer-map.json`の全順序でPSDを書き出し、再読込後も順序が
保たれることを確認します。構造QAでは、必須レイヤー、名前の重複、表示可能な画素、
PSDの書き戻し、上記の重要な前後関係を確認します。入力、受け取ったファイル、各成果物、
出力PSDのハッシュは処理全体の別工程で確認します。表情QAでは、ファイルの有無と位置、口が小さな描画として
収まっていることを確認し、閉じ口の過剰な塗りつぶしや明るい大面積の塗りを検出します。
数値検査だけでは肌との色差や切り抜き境界を判定しきれないため、目視確認も必要です。

動作品質の確認にはレンダラーで収録した証拠が必要です。まばたき、口の切り替え、
連続リップシンク、髪だけの動き、全身の待機動作、ドラッグ後の慣性、顔パーツの安定、
意図しない継ぎ目の露出を対象にします。

## 内蔵レンダラーでの動作検査

```bash
npm run still2rig-psd -- motion-qa demo
npm run still2rig-psd -- motion-qa demo --negative-fixture
```

`motion-qa`はジョブのPSDをプレビュー用レンダラーでヘッドレスChromiumを使って開き、
契約にあるすべての状態を、モデルと同じ倍率・緑一色の背景で収録します。収録画像と
`motion-qa.json`は`.still2rig-psd/jobs/<job>/reports/motion-qa/`に保存され、結果は
ジョブの`result.motionQa`にも記録されます。

| 検査 | 測り方 |
| --- | --- |
| 目・口の変化 | 開いた状態と閉じた状態で、目または口の範囲のうちRGBの最大変化が24を超える画素数。 |
| 目以外の安定 | まばたき中、目と眉以外のRGB平均絶対誤差(フルスケールに対する%)。 |
| 毛先 | 髪だけを動かしたとき、髪の下から4分の1の範囲で変化した画素の割合。 |
| 顔パーツの固定 | 髪だけを動かしたときの、目と口の範囲の平均絶対誤差。 |
| 顔パーツの配置 | 各フレームで目と口の位置を追跡し、両目の間隔と、目の位置から予測した口の位置を、PSD本来の配置と比べます。頭全体の移動や回転は差として数えません。 |
| 継ぎ目 | 静止時の輪郭の内側に、緑の背景が穴として現れた画素数。外側とつながった背景と、見えている髪の範囲の背景は、動きとして想定内とみなします。 |

`--negative-fixture`は`mouth_close`を右へ24px動かしたコピーで検査し、FAILになる
ことを確認します。検査の変更後に、ずれを検出できる状態が保たれているかを確かめる
ために使います。

対象は内蔵レンダラーだけです。見えている髪のすぐ横に開いたすき間や、動きが自然に
見えるかは目視で確認してください。物理演算の収録はタイミングに左右されるため、
しきい値付近の結果は実行ごとに変わる場合があります。
